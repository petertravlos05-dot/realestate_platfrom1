# S3 File Storage Security

## Overview

All S3 files are stored in a **private bucket** with **no public access**. File access is controlled via **short-lived signed URLs** generated only after authorization checks.

## Security Model

### 1. Private Bucket Configuration

**Bucket Policy Requirements:**
- **Block Public Access**: All public access must be blocked
- **ACL**: All objects uploaded with `ACL: 'private'` (or no ACL, which defaults to private)
- **No Public Read**: No bucket policy should allow `s3:GetObject` for `*` principal

**AWS Console Configuration:**
1. Go to S3 bucket → Permissions → Block Public Access
2. Enable **all** public access blocks
3. Go to Bucket Policy → Ensure no policy allows public `s3:GetObject`

**Expected Bucket Policy:**
```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Deny",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::your-bucket-name/*"
    }
  ]
}
```

**Note:** The above policy explicitly denies public access. Alternatively, ensure Block Public Access is enabled (recommended).

### 2. File Upload Security

**Upload Process:**
1. File validated (MIME type, magic bytes, forbidden extensions)
2. Secure filename generated (UUID-based)
3. File uploaded to S3 with `ACL: 'private'` (or no ACL)
4. S3 key stored in database (not direct URL)

**Upload Endpoints:**
- `POST /api/properties/images` - Property images
- `POST /api/properties/:id/progress/documents` - Property documents (requires ownership)

**Response:**
- Returns S3 key (not direct URL)
- Client must request signed URL separately via `/api/files/download-url`

### 3. File Access via Signed URLs

**Download Endpoint:**
```
GET /api/files/download-url?key=<s3Key>&expiresIn=<seconds>
```

**Authorization Flow:**
1. User authenticates (JWT token required)
2. S3 key extracted from query parameter
3. Property ID extracted from S3 key
4. Authorization check:
   - User owns property, OR
   - User is participant in transaction (buyer/seller/agent), OR
   - User is admin
5. If authorized: Generate signed URL (expires in 60-300 seconds)
6. If unauthorized: Return 403

**Signed URL Properties:**
- **Expiration**: 60-300 seconds (default: 300 = 5 minutes)
- **Access**: Read-only (`GetObject` command)
- **Scope**: Single file only
- **Revocation**: Cannot be revoked, but expires quickly

**Example Request:**
```bash
curl -H "Authorization: Bearer <token>" \
     "https://api.domain.com/api/files/download-url?key=properties/123/document/abc.pdf&expiresIn=300"
```

**Example Response:**
```json
{
  "url": "https://bucket.s3.region.amazonaws.com/key?X-Amz-Algorithm=...&X-Amz-Expires=300&...",
  "expiresAt": "2025-01-06T12:05:00.000Z",
  "expiresIn": 300
}
```

### 4. File Listing Security

**Document Listing Endpoint:**
```
GET /api/properties/:id/progress/documents
```

**Security:**
- Requires property ownership (`requirePropertyOwnership` middleware)
- Returns file metadata (key, type, size, uploadedAt)
- **DOES NOT** return direct S3 URLs
- Client must request signed URL for each file separately

**Response Format:**
```json
{
  "documents": [
    {
      "key": "properties/123/document/abc.pdf",
      "type": "document",
      "status": "uploaded",
      "uploadedAt": "2025-01-06T12:00:00.000Z",
      "size": 1024
    }
  ]
}
```

### 5. Authorization Rules

**Who Can Access Property Files:**

1. **Property Owner** (`property.userId === userId`)
   - Can access all files for their properties

2. **Transaction Participants**
   - Buyer (`transaction.buyerId === userId`)
   - Seller (`transaction.sellerId === userId`)
   - Agent (`transaction.agentId === userId`)
   - Can access files for properties in their transactions

3. **Admins** (`userRole === 'ADMIN' || 'SUPER_ADMIN'`)
   - Can access all files

4. **Others**
   - **Cannot** access files (403 Forbidden)

### 6. S3 Key Structure

**Format:**
```
{propertyId}/{documentType}/{secureFilename}
```

**Examples:**
- `properties/123/document/abc.pdf` → Property 123, document type "document"
- `properties/123/image/xyz.jpg` → Property 123, image
- `123/document/abc.pdf` → Property 123, document (alternative format)

**Property ID Extraction:**
- If key starts with `properties/`, propertyId is second segment
- Otherwise, propertyId is first segment

### 7. Audit Logging

**Logged Events:**
- File download requests (success/failure)
- Authorization failures
- S3 key (filename only, not full path)
- Property ID
- Expiration time

**Not Logged:**
- Full S3 keys
- Signed URLs
- File contents
- User PII

### 8. Error Handling

**Common Errors:**

1. **401 Unauthorized**
   - No authentication token provided

2. **403 Forbidden**
   - User not authorized to access file
   - Invalid file path (cannot extract property ID)

3. **400 Bad Request**
   - Missing `key` parameter
   - Invalid `expiresIn` (must be 60-3600 seconds)

4. **500 Internal Server Error**
   - S3 not configured
   - Failed to generate signed URL

## Migration Guide

### Backend Changes

**Before:**
```typescript
const fileUrl = `https://${bucket}.s3.${region}.amazonaws.com/${s3Key}`;
res.json({ fileUrl });
```

**After:**
```typescript
// Return S3 key only
res.json({ s3Key });
// Client requests signed URL via /api/files/download-url?key=${s3Key}
```

### Frontend Changes

**Before:**
```typescript
const fileUrl = `https://${bucket}.s3.${region}.amazonaws.com/${key}`;
<img src={fileUrl} />
```

**After:**
```typescript
// Request signed URL
const response = await fetch(`/api/files/download-url?key=${key}`, {
  headers: { Authorization: `Bearer ${token}` }
});
const { url, expiresAt } = await response.json();
<img src={url} />
```

## Testing

### Manual Testing

**Test Authorization:**
```bash
# User A uploads file for property 123
# User B tries to access file → Should get 403

curl -H "Authorization: Bearer <userB_token>" \
     "https://api.domain.com/api/files/download-url?key=properties/123/document/file.pdf"
# Expected: 403 Forbidden
```

**Test Expiration:**
```bash
# Request signed URL with 60 second expiration
# Wait 61 seconds
# Try to access URL → Should fail (expired)
```

## Security Checklist

- [x] Bucket configured as private (no public access)
- [x] All uploads use `ACL: 'private'` or no ACL
- [x] No direct S3 URLs returned to clients
- [x] Signed URLs generated only after authorization
- [x] Signed URLs expire quickly (5 minutes default)
- [x] File listing requires ownership check
- [x] Authorization checks enforced (owner/transaction participant/admin)
- [x] Audit logging implemented
- [x] No S3 keys or URLs logged
